# 시스템 구성

> 2026-10-25 재계획에 따른 새 구조입니다. 휴대폰 쪽은 Android 앱 대신 모바일 웹으로 만들고, 계정(회원가입·로그인·보호자 등록)과 웹 푸시 알림을 넣습니다. 통신 형식은 초안이며 10/26에 팀이 확정합니다. 이전 구조(Pi 단독, L3/L4 두 프로세스)는 저장소의 기존 시험 구현에 남아 있습니다.

모든 기기는 시연장의 같은 공유기(또는 핫스팟)에 연결합니다. 서버 PC는 고정 IP를 받도록 설정해 클라이언트가 같은 주소로 접속하게 합니다. 웹 푸시는 브라우저 회사의 푸시 서비스를 거치므로 서버 PC와 보호자 휴대폰이 인터넷에도 연결되어 있어야 합니다.

휴대폰 쪽은 앱을 설치하지 않고, 서버가 제공하는 웹페이지를 휴대폰 브라우저로 엽니다. 휴대폰 브라우저는 HTTPS 페이지에서만 카메라·마이크·서비스 워커(웹 푸시)를 쓸 수 있으므로 서버는 HTTPS(`https://`, `wss://`)로 동작해야 합니다. 시연용으로는 mkcert 같은 도구로 인증서를 만들고, 그 인증 기관을 휴대폰과 Pi에 설치해 경고 없이 접속하게 합니다.

## 계정과 권한

| 개념 | 내용 |
| --- | --- |
| 계정 | 이메일(아이디), 비밀번호, 이름. 계정 종류는 하나이며, 다른 계정의 보호자로 연결되면 그 사람의 보호자가 됨 |
| 사용자 | 기기를 등록하고 감시받는 사람 (예: 어르신 계정) |
| 보호자 | 사용자가 마이페이지에서 등록한 다른 계정. 보호자도 회원가입이 되어 있어야 함 |
| 보호자 등록 | 사용자가 보호자의 이메일을 입력 → 보호자의 마이페이지에 요청이 보임 → 보호자가 수락하면 연결. 본인 동의 없이 남의 경보를 받지 않게 하기 위함 |
| 기기 | 사용자 계정에 속함. 휴대폰은 로그인한 채 카메라 감지 화면을 열면 그 계정의 기기로 등록. Pi는 마이페이지에서 발급한 기기 키로 접속 |
| 권한 | 사용자는 자기 기기와 이벤트만, 보호자는 연결된 사용자의 상태와 이벤트만 볼 수 있음. 경보 해제는 사용자 본인(현장 화면 포함)과 연결된 보호자만 가능 |

### 관리자

시스템을 운영하는 팀이 관리자입니다. 관리자 계정은 만들지 않고, 관리자 페이지(`/admin`)와 관리자 API(`/admin/api/...`)는 **서버 PC 자신에서 연 요청만** 받습니다(`server/admin.py`).

- 접속 주소가 루프백(127.0.0.1, ::1)이어야 하고, `Host` 머리글도 `localhost`·`127.0.0.1`·`[::1]`이어야 합니다(DNS 리바인딩 차단).
- 상태를 바꾸는 요청은 같은 출처의 `Origin`과 `X-Admin-Request: 1` 머리글이 있어야 합니다(서버 PC 브라우저를 이용한 CSRF 차단).
- 맞지 않으면 404로 답해 같은 Wi-Fi의 다른 기기에는 관리자 페이지가 있다는 것도 알리지 않습니다. `FALL_ADMIN=0`이면 아예 끕니다.
- 관리자 동작은 사용자 세션과 상관없고, 상태를 바꾼 동작은 서버 로그에 남깁니다.

관리자가 계정을 정지하면 그 사용자는 로그인할 수 없고, 기존 세션·열린 보호자 화면·그 사용자 기기의 카메라 연결이 끊기며 기기의 새 접속도 거부됩니다. 사용 방법은 [server/README.md](../server/README.md#관리자-페이지)에 있습니다.

비밀번호는 해시(bcrypt 또는 argon2)로만 저장합니다. 로그인은 서버 세션과 HttpOnly·Secure 쿠키로 유지합니다. 이메일 인증과 비밀번호 찾기는 이번 범위에 넣지 않습니다.

## 처리 흐름

1. Pi와 휴대폰(카메라 감지 화면)은 각자 기기 ID로 서버에 접속해 JPEG 프레임을 초당 약 10장 보냅니다.
2. 서버는 기기별로 따로 자세 추정, 특징 계산, 상태 머신을 돌립니다.
3. 하강 속도 피크 뒤 누운 자세가 일정 시간(T1) 이어지면 그 기기에 낙상 의심 이벤트를 만듭니다. 넘어진 뒤 뒤척이거나 몸 일부가 화면 밖으로 나가 1초 이하로 끊기는 것은 이어서 잽니다.
4. 서버가 그 기기에 음성 확인을 요청합니다. Pi는 스피커로, 휴대폰은 브라우저로 안내 음성을 재생하고, 몇 초 녹음해 서버로 보냅니다. 화면의 '괜찮아요' 버튼으로도 응답할 수 있습니다.
5. 서버는 Whisper로 인식한 문장을 키워드로 분류합니다. '괜찮다'면 해제, 도움 요청·무응답·장치 오류면 경보로 바꿉니다.
6. 경보가 나면 서버는 그 기기 주인의 보호자 목록을 찾아, 열려 있는 보호자 화면에는 WebSocket으로, 푸시를 켠 보호자 휴대폰에는 웹 푸시로 알립니다. 푸시 알림을 누르면 보호자 화면이 열립니다.
7. 현장 화면·카메라 감지 화면의 '괜찮아요' 버튼이나 보호자 화면에서 경보를 끝냅니다.

## 상태 흐름

기기별 감지 상태: 정상 → 하강 감지 → 낙상 의심 (이벤트가 끝날 때까지 유지)

이벤트 상태: 음성 확인 중 → 해제 또는 경보 → (버튼으로) 종료

같은 기기에서 진행 중인 이벤트가 있으면 새 이벤트를 만들지 않습니다. 이벤트가 끝나면 그 기기의 감지 상태를 정상으로 되돌려 다시 감시합니다.

## 통신 형식 초안 (10/26 확정)

웹페이지

| 주소 | 화면 |
| --- | --- |
| `GET /signup`, `GET /login` | 회원가입, 로그인 |
| `GET /mypage` | 내 정보, 보호자 등록·요청 수락, 내 기기 목록·Pi 기기 키 발급, 알림 켜기 |
| `GET /camera` | 휴대폰 카메라 감지 (로그인 필요) |
| `GET /guardian` | 보호자 화면 (로그인 필요) |
| `GET /kiosk` | Pi 현장 화면 (기기 키로 접속) |
| `GET /admin` | 관리자 페이지 (서버 PC에서만, 아래 '관리자' 참고) |

API

| 연결 | 방향 | 내용 |
| --- | --- | --- |
| `POST /api/signup`, `POST /api/login`, `POST /api/logout` | 웹 → 서버 | 계정. 로그인 성공 시 세션 쿠키 발급 |
| `GET /api/me` | 웹 → 서버 | 내 정보, 내 보호자 목록, 내가 보호하는 사용자 목록, 받은 보호자 요청 |
| `POST /api/guardians` | 웹 → 서버 | `{"email": ...}` 보호자 등록 요청 |
| `POST /api/guardians/{id}/accept`, `DELETE /api/guardians/{id}` | 웹 → 서버 | 요청 수락, 연결 해제 |
| `POST /api/devices` | 웹 → 서버 | Pi 기기 추가, 기기 키 발급 (키는 이때 한 번만 보여 줌) |
| `POST /api/push/subscribe` | 웹 → 서버 | 웹 푸시 구독 정보 저장 |
| `WS /ws/camera` | 기기 → 서버 | 휴대폰은 세션 쿠키, Pi는 기기 키로 인증. 바이너리 메시지 1개 = JPEG 프레임 1장 (640×480, 품질 70 안팎) |
| | 서버 → 기기 | `{"type": "voice_check", "event_id": 12}` 음성 확인 요청, `{"type": "state", "state": "NORMAL" \| "SUSPECT" \| "ALARM"}` 상태 변경 |
| `POST /api/events/{id}/voice` | 기기 → 서버 | 응답 녹음 (Pi: wav 16kHz 모노, 휴대폰: MediaRecorder webm) |
| `WS /ws/guardian` | 서버 → 보호자 화면 | 접속 직후 `{"type": "snapshot", "devices": [...], "active_events": [...]}`, 이후 `{"type": "device", ...}`, `{"type": "event", ...}` |
| `GET /api/events?limit=N` | 웹 → 서버 | 볼 권한이 있는 최근 이벤트 |
| `POST /api/events/{id}/clear` | 웹 → 서버 | '괜찮아요' 버튼, 경보 종료 |

보호자 화면이 다시 연결되면 `snapshot`으로 진행 중인 경보를 다시 받습니다. 연결이 끊긴 동안 생긴 경보를 놓치지 않기 위해서입니다.

## 장애 처리

| 상황 | 처리 |
| --- | --- |
| 서버 연결 끊김 | Pi 클라이언트와 웹페이지는 몇 초 간격으로 재연결. 현장 화면·카메라 감지 화면·보호자 화면에 '감지 중단' 표시 |

| 서버 재시작 | 끝나지 않은 이벤트는 '중단'으로 기록. 경보 상태였던 이벤트는 다시 연결된 보호자 화면에 계속 보여 줌 |

## 데이터와 개인정보

- 카메라 프레임은 같은 네트워크 안의 서버로만 보내고, 서버는 메모리에서 처리한 뒤 버립니다. 원본 영상은 저장하지 않습니다.
- 응답 녹음은 인식이 끝나면 지웁니다. 기본은 분류 결과(괜찮음·도움 요청 등)만 저장합니다.
- 웹 푸시 알림 내용에는 영상·음성을 넣지 않고, 사용자 이름·시각·판정만 담습니다.
- 계정 정보는 이메일, 이름, 비밀번호 해시만 저장합니다.
- 이벤트 기록: 기기, 발생 시각, 판정 시점의 특징값, 음성 확인 결과, 경보 여부, 종료 방법과 시각.
- 테스트 영상 촬영은 대상자 동의를 받고, 보관 기간과 접근 권한을 정한 뒤 진행합니다.
