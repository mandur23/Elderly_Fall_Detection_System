# 상용화 준비 점검

> 이 프로젝트는 교육·연구용 프로토타입으로 시작했습니다(README '사용 범위'). 상업적으로 판매·운영하려면 코드 외에도 검증, 법·규제, 라이선스, 운영 체계가 필요합니다. 이 문서는 현재 상태와 남은 일을 정리한 것이며, 법률·규제 항목은 전문가 확인이 필요합니다.

## 1. 현재 코드에 반영된 것

| 영역 | 내용 |
| --- | --- |
| 실기기 동작 | Pi 카메라 모듈(picamera2)·USB 카메라, MediaPipe Tasks API, 마이크 장치 선택, 안내 음성 대체(합성 음성·알림음) |
| 무인 운영 | systemd 자동 시작·재시작, L3 워치독, 카메라 자동 재연결, 재시작 시 미완료 이벤트 정리·해제 안 된 경보 복원·끊긴 알림 재전송 |
| 장애 알림 | 감지 중단(프로세스·카메라·모델·마이크)이 지속되면 보호자에게 알림, 복구 알림, 일일 상태 보고, 평소에도 마이크 입력 주기 점검 |
| 경보 | 현장 경보음, 보호자 알림 재시도, 지연 전송 시각 표시, 해제 알림, 중복 경보 방지 |
| 안전 쪽 판단 | 무응답·불분명·마이크 무음은 경보로 처리, "안 괜찮아요" 같은 부정 표현은 도움 요청으로 분류 |
| 보안 | 서버는 127.0.0.1에만 열림, L3→L4 내부 API 키, 설정 파일 권한 600 |
| 개인정보 | 영상·음성 원본 미저장, 인식 문장 원문 기본 미저장, 보관 기간 설정 |
| 검증 도구 | 장치 점검(`tools.check_device`), 영상 평가·임계값 탐색(`tools.evaluate`), 공개 데이터 준비(`tools.prepare_urfall`), 자세 추정 데모(`tools.pose_demo`), 시나리오 자동 확인(`run_demo.py --auto`) |

## 2. 상용화 전에 반드시 필요한 것

### 2.1 성능 검증 (가장 중요)

판정 기준은 공개 낙상 데이터셋(UR Fall, 낙상 30·일상 40)으로 측정해 정했습니다([성능 평가 기록](EVALUATION.md)). 다만 저해상도 연출 영상이고 카메라 위치·사용자가 실제 설치 환경과 다르므로, 상용 수준의 근거로는 부족합니다. UR Fall 데이터셋은 비상업 라이선스(CC BY-NC-SA 4.0)라 상업 제품 개발에 쓰려면 별도 허락이 필요합니다.

- 동의를 받은 연출 영상과 실제 설치 환경 영상으로 `tools.evaluate`를 돌려 재현율, 오경보율, 감지 지연을 측정
- 조명(야간 포함), 카메라 각도·거리, 가림(가구), 여러 명이 있는 경우, 휠체어·보행 보조기 사용자 등 조건별 측정
- 장시간(수일 이상) 실내 연속 운용으로 하루당 오경보 횟수와 메모리·발열·안정성 확인
- 목표 수치와 합격 기준을 팀이 정해 TEST_PLAN.md에 기록

알려진 한계(현재 판정 방식):

- 천천히 주저앉거나 미끄러지듯 넘어지면 하강 속도 피크가 작아 놓칠 수 있음 (UR Fall에서 놓친 4개가 이 경우)
- 넘어진 뒤 상체를 세우고 바닥에 앉아 있으면 정상으로 돌아감 (일어나지 못하는 상황 미감지)
- 빠르게 몸을 낮춘 뒤 화면 밖으로 사라지면 낙상 의심으로 볼 수 있음 (음성 확인에서 대답하면 해제)
- 음성 인식은 합성 음성으로만 시험함. 실제 노인 목소리에서 '괜찮아요'를 놓치면 경보가 남
- 카메라에 보이지 않는 곳(욕실 등)은 감지 불가
- 한 사람만 추적 (가장 확실한 한 명)

### 2.2 법·규제 (전문가 확인 필요)

| 항목 | 확인할 내용 |
| --- | --- |
| 의료기기 해당 여부 | 진단·치료 목적 표현을 쓰면 의료기기로 분류될 수 있음. 제품 설명·광고 문구를 '안전 보조' 범위로 제한할지, 식약처 판단을 받을지 결정 |
| 개인정보보호법 | 영상·음성 처리에 대한 동의, 건강 관련 정보(낙상 기록)의 민감정보 해당 여부, 보관 기간, 제3자(보호자) 제공 동의, 처리방침 |
| 영상정보처리기기 | 설치 장소(가정, 요양시설 등)에 따라 안내판·운영 규정 등 요구 사항이 다를 수 있음 |
| 전파·전기 안전 인증 | 하드웨어를 완제품으로 판매한다면 KC 인증 대상 여부 |
| 책임 고지·약관 | 오경보·미감지 시 책임 범위, '응급 신고를 대신하지 않음' 고지 |

### 2.3 라이선스

| 구성 요소 | 라이선스 | 비고 |

| MediaPipe, 자세 모델 | Apache-2.0 | 고지 의무 확인 |

| 텔레그램 봇 | 텔레그램 이용약관 | 상용 서비스 알림 채널로 적합한지, 문자·카카오 알림톡 등 대안 검토 |

### 2.4 운영 체계

- 알림 이중화: 인터넷 장애 시 경보가 늦어짐. LTE 모뎀이나 문자 알림 등 대체 경로, 정전 대비 UPS 검토
- 원격 관리: 여러 대를 운영하려면 원격 상태 확인, 업데이트 배포, 장애 접수 체계 필요 (현재는 기기별 수동 관리)
- 보안 운영: OS 보안 업데이트, SSH 비밀번호 로그인 차단, 기본 계정 변경, 저장 장치 암호화 검토
- 고객 지원: 설치 안내, 오경보 신고 처리, 보호자 등록·변경 절차

## 3. 권장 순서

1. 실제 장치에 설치하고 `tools.check_device`로 장치 조건 확인
2. 연출 영상과 공개 데이터로 `tools.evaluate` 측정, 임계값 결정
3. 시험 가정(동의 받은 팀원 환경)에서 수일 연속 운용, 오경보·장애 기록
4. 법·규제·라이선스 검토 결과에 따라 제품 범위와 문구 확정
5. 알림 채널과 운영 체계 결정 후 소규모 시범 운영
