# 성능 평가 기록

> 2026-10-15 측정. 교육용 시연 범위의 동작 확인이며, 의료기기 수준의 성능 검증이 아닙니다.
> 공개 영상과 합성 음성으로 측정했으므로 실제 설치 환경(카메라 위치, 노인 사용자, 실제 목소리)에서 다시 측정해야 합니다.

## 1. 낙상 감지 (UR Fall Detection Dataset)

### 자료와 방법

| 항목 | 내용 |
| --- | --- |
| 자료 | UR Fall Detection Dataset cam0 영상, 낙상 30개·일상 동작 40개 (컬러 320×240, 30fps) |
| 카메라 | 약 1m 높이, 바닥과 평행하게 설치 (권장 설치 방식보다 낮음) |
| 처리 | `tools/prepare_urfall.py`로 컬러 절반을 잘라 `tools/evaluate.py`로 측정. 실제 장치와 같은 10fps, 640×480 |
| 모델 | MediaPipe Pose lite (`pose_landmarker_lite.task`), mediapipe 1.1.1, Python 3.11, Windows PC |
| 판정 | 영상에서 '낙상 의심'이 한 번이라도 나오면 감지. 낙상 영상이면 성공, 일상 영상이면 오경보 |

UR 영상은 넘어지고 1~2초 뒤에 끝나서 누움 시간(2초)을 채우기 어렵습니다. 그래서 두 조건으로 측정했습니다.

- **A. 영상 그대로**
- **B. 영상이 끝난 뒤 마지막 장면을 3초 더 유지** (`--hold 3`). 실제로는 넘어진 사람이 계속 누워 있다고 가정한 모의 실험입니다.

출처: http://fenix.ur.edu.pl/~mkepski/ds/uf.html (CC BY-NC-SA 4.0, 비상업·학술용).
Kwolek B., Kepski M., Human fall detection on embedded platform using depth maps and wireless accelerometer, Computer Methods and Programs in Biomedicine 117(3), 2014.

### 결과

| 설정 | A 감지 | A 오경보 | B 감지 | B 오경보 |
| --- | --- | --- | --- | --- |
| 이전 (하강 속도 2.0, 누움 2초) | 0/30 | 0/40 | 5/30 | 0/40 |
| 하강 속도만 1.5로 | 2/30 | 0/40 | 14/30 | 0/40 |
| **현재 (하강 속도 1.5, 누움 2초, 아래 규칙 2개)** | 2/30 | 1/40 | **26/30** | **1/40** |
| 참고: 현재에서 누움 1초 | 9/30 | 7/40 | 26/30 | 7/40 |

누움 시간을 줄이면 오경보가 크게 늘어 2초를 유지했습니다.

### 찾은 문제와 고친 것

1. **하강 속도가 처리 속도에 따라 달라짐.** 3프레임 전과 비교해서 30fps에서는 0.1초, 10fps에서는 0.3초 구간이 됐고, 같은 낙상도 값이 세 배까지 달랐습니다(fall-04: 5.99 → 1.96). 시간 기준 0.3초 구간으로 바꿨습니다(`DESCENT_VELOCITY_WINDOW_SECONDS`).
2. **하강 속도 기준이 10fps에서 너무 높음.** 2.0 → 1.5. 낙상의 최고 하강 속도는 1.31~4.19, 일상 동작은 0.35~5.67로 겹쳐서 하강 속도만으로는 구분할 수 없고, 누움 확인이 함께 필요합니다.
3. **넘어진 뒤 사람이 안 보임.** 카메라 쪽으로 넘어져 화면 아래로 잘리면 넘어진 뒤 프레임의 17%에서 MediaPipe가 자세를 찾지 못했습니다(어깨·엉덩이 신뢰도 규칙에서 버려진 프레임은 0). 하강 감지 뒤 사람이 안 보이면 누운 것과 같이 보도록 했습니다(`MISSING_COUNTS_AS_LYING`). 가장 큰 개선(14 → 26)이 여기서 나왔습니다.
4. **쓰러지기 시작한 순간 바로 정상 복귀.** 넘어지기 시작할 때는 몸통이 아직 서 있어 '일어섬'으로 판단했습니다. 일어선 자세가 0.5초 이어져야 정상으로 돌아가게 했습니다(`STANDING_CONFIRM_SECONDS`).

짧은 '사람 없음' 끊김을 누움 시간에서 봐주는 방식도 시험했지만 효과가 작고(낙상 +0~2) 오경보가 늘어 넣지 않았습니다.

### 남은 한계

- **놓친 낙상 4개(B):** fall-03·20·23·30. 천천히 주저앉거나(최고 하강 속도 1.31~1.41) 앉은 자세로 끝나는 낙상입니다. 몸통이 세워진 채 바닥에 앉아 있으면 '누움'이 아니어서 감지하지 못합니다.
- **오경보 1개:** adl-30. 바닥에 손과 무릎을 짚고 엎드린 뒤 화면에서 사라진 경우로, 3번 규칙 때문에 생긴 오경보입니다. 이후 음성 확인에서 대답하면 해제됩니다.
- 누움 시간 1초 이하에서 생기는 오경보는 모두 바닥으로 몸을 낮추는 동작(엎드리기, 가구 밑 보기)이었습니다.
- 카메라가 낮으면 넘어진 사람이 화면 아래로 잘립니다. 높은 곳에서 바닥 전체를 내려다보게 설치해야 합니다.
- 저해상도, 연출 낙상(매트 위), 젊은 성인 자료입니다. 큰 자세 모델(full·heavy)은 비교하지 않았습니다.

## 2. 음성 확인 (Vosk 한국어 소형 모델 0.22)

### 방법

Windows 한국어 합성 음성(Microsoft Heami)으로 16kHz 문장 16개를 만들어, `VoskVoiceChecker.listen()`에 마이크 녹음 대신 넣었습니다. '괜찮다' 4개, 도움 요청 3개, 부정 표현("안 괜찮아요") 1개, 관계없는 말 7개(예: "음, 뭐라고요?", "잠깐만요"), 조용함 1개입니다.

### 결과

| 방식 | '괜찮다' 인식 | 도움 요청 | 부정 표현 | 잘못된 '괜찮다' |
| --- | --- | --- | --- | --- |
| 자유 인식만 (이전) | 0/4 | 3/3 | 불분명 | 0/7 |
| 응답 문구로 제한한 인식만 | 4/4 | 3/3 | 도움 요청 | **1/7** ("음, 뭐라고요?" → "응 문제 없어요") |
| **현재: 둘을 합침** | 3/4 | 3/3 | 불분명 | **0/7** |

- 자유 인식은 '괜찮아요'를 "된 채 네요" 같은 말로 잘못 알아들었습니다. 이대로면 괜찮다고 대답해도 경보가 납니다.
- 문구 제한 인식은 엉뚱한 말도 가장 가까운 문구로 바꿔 버립니다. 잘못된 '괜찮다'는 가장 위험한 오류이므로, 문구 제한 인식은 모든 단어 신뢰도가 0.9 이상일 때만 씁니다(`VOICE_GRAMMAR`, `VOICE_GRAMMAR_MIN_CONF`).
- 알아듣지 못한 '괜찮다'와 부정 표현은 '불분명'이 되어 한 번 더 묻고, 끝까지 불분명하면 경보로 갑니다(안전 쪽).
- 실제 마이크로 0.3초 입력 점검(`MIC_CHECK_INTERVAL_SECONDS`)이 정상 동작하는 것을 확인했습니다.

### 남은 한계

- 합성 음성 기준입니다. 실제 노인의 목소리·발음·생활 소음에서 다시 측정하고 신뢰도 기준(0.9)을 조정해야 합니다.

## 3. PC에서 실제 장치로 전체 흐름 확인

| 항목 | 내용 |
| --- | --- |
| 환경 | Windows 11 PC, USB 웹캠, 노트북 마이크 (Raspberry Pi 아님) |
| 구성 | L4 서버(Vosk, 실제 마이크) + L3 감지(MediaPipe, fall-10 영상을 10fps 실시간으로 입력) + 현장 화면(브라우저) |
| 결과 | 하강 감지 → 낙상 의심 보고 → 음성 확인 2회(응답 없음) → 경보('알림 미설정' 표시) → 화면 '괜찮아요' 버튼으로 해제 → L3 감시 재개 → 영상 반복에서 재감지 |
| 웹캠 | `tools.pose_demo`로 웹캠 실시간 자세 추정·판정 표시 확인 |
| 확인 못 함 | Raspberry Pi 실기기, 텔레그램 실제 전송, 녹음한 안내 음성, 스피커 경보음 |

## 재현 방법

```bash
pip install -r requirements.txt -r requirements-device.txt
python -m tools.prepare_urfall data/urfall --download
python -m tools.evaluate data/urfall/rgb/labels.csv --hold 3
python -m tools.evaluate data/urfall/rgb/labels.csv --hold 3 --grid DESCENT_VELOCITY_PEAK=1.25,1.5,2 --grid T1_LYING_SECONDS=1,2
python -m tools.pose_demo --source data/urfall/fall-10-cam0.mp4 --right-half
```
