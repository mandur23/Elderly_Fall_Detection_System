# 프로젝트 계획

> 상태: 2026-10-25 재계획 (같은 날 Android 앱 → 모바일 웹으로 변경) · 최종 시연·발표: 2026년 11월 4~6일 (이 계획은 가장 이른 11월 4일(수) 기준)

## 배경과 목적

고령자나 1인 가구에서 낙상이 발생하면 즉시 도움을 요청하기 어려울 수 있습니다. 이 프로젝트는 실내 카메라로 자세와 움직임을 분석해 낙상 의심 상황을 알아차리고, 음성 확인과 알림을 연결하는 비착용형 안전 모니터링 프로토타입을 만드는 것을 목표로 합니다.

## 재계획 이유

| 문제 | 내용 | 바꾸는 방향 |
| --- | --- | --- |
| Pi 처리 속도 | Raspberry Pi 5에서 YOLO-Pose가 초당 수 프레임 수준밖에 나오지 않음 | 영상 분석을 중앙 서버(팀원 PC)로 옮기고 Pi는 현장 단말로 사용 |
| 음성 품질 | 마이크 입력이 작고 잡음이 많음 | 마이크 장비·입력 설정을 개선하고, 음성 인식을 서버의 Whisper로 옮김 |
| 구조 확장 | 휴대폰 카메라로도 감지하고, 보호자가 휴대폰으로 상태를 보고 싶음 | 중앙 서버 + 여러 클라이언트(Pi, 모바일 웹) 구조로 변경 |
| 모바일 형태 | 처음에는 휴대폰 쪽을 Android 네이티브 앱으로 계획함 | 앱 대신 서버가 제공하는 모바일 웹으로 보호자 화면과 휴대폰 카메라 감지를 만듦 |
| 코드 이해도 | 기존 시험 구현은 AI로 작성되어 팀이 구조를 충분히 이해하지 못함 | 새 구조로 처음부터 다시 작성. 기존 코드는 참고용으로 남김 |

## 최종 결과물

- 중앙 서버(팀원 PC)에서 영상 분석, 음성 인식, 이벤트 관리, 경보 전달을 처리하는 시스템
- Raspberry Pi 현장 단말: 카메라 영상 전송, 안내 음성 재생·녹음, 현장 화면
- 모바일 웹: 휴대폰 브라우저로 여는 보호자 화면(경보 수신, 현재 상태, 이벤트 기록)과 휴대폰 카메라 감지 화면
- 안전하게 촬영한 테스트 영상과 공개 자료를 이용한 검증 결과
- 실행 방법, 구성 방법, 알려진 한계를 설명하는 문서

## 구현 범위

| 구분 | 내용 |
| --- | --- |
| 필수 (이번 시연) | Pi 카메라 → 서버 낙상 의심 판정 → Pi 음성 확인 → 해제 또는 경보 → 모바일 웹 경보 수신 · 이벤트 기록 · Pi 현장 화면 · 휴대폰 카메라 감지 |
| 향후 확장 | 브라우저를 닫아도 오는 푸시 알림과 외부망 알림, 휴대폰에서 현장 응답, 장시간 미동 등 추가 이벤트, 긴급구조 체계 연계 |

범위는 줄이지 않기로 했습니다. 대신 중간 점검일(10/28, 10/31)에 진행 상황을 확인하고, 늦어진 작업을 바로 조정합니다. 의료 진단과 실제 응급기관 자동 신고는 이번 범위에 포함하지 않습니다.

## 역할 분담

| 담당 | 맡는 부분 |
| --- | --- |
| 서버 + Pi 담당 | 중앙 서버(영상 수신, YOLO-Pose, 낙상 판정, Whisper 음성 인식, 이벤트 DB, WebSocket 전달), Pi 클라이언트(카메라 전송, 음성 재생·녹음, 키오스크 화면) |
| 웹 담당 | 모바일 웹(HTML·JavaScript): 보호자 화면(상태·경보·기록), 휴대폰 카메라 감지 화면, Pi 현장 화면(키오스크) |
| 공동 | 서버-클라이언트 메시지 형식, 테스트 영상 촬영, 통합 테스트, 발표 준비 |

두 사람이 동시에 작업하려면 메시지 형식([ARCHITECTURE.md](ARCHITECTURE.md) '통신 형식 초안')을 첫날 확정해야 합니다. 웹 담당은 서버가 완성되기 전에도 이 형식대로 응답하는 가짜 서버로 화면을 먼저 만들 수 있습니다.

## 정한 결정 (2026-10-25)

| 항목 | 결정 |
| --- | --- |
| 전체 구조 | 중앙 서버 + 클라이언트(Pi 현장 단말, 모바일 웹) |
| 서버 위치 | 팀원 노트북·데스크톱. 시연장에 가져가 같은 네트워크에서 실행 |
| 영상 처리 | 클라이언트가 카메라 프레임을 서버로 보내고 서버에서 분석. 원본은 저장하지 않고 메모리에서만 처리 |
| 낙상 감지 | YOLO-Pose 관절 추정 + 규칙(몸통 각도, 종횡비, 하강 속도) |
| 음성 확인 | Pi가 안내 음성 재생·응답 녹음, 서버의 Whisper(faster-whisper)로 인식 후 키워드 분류 |
| 마이크 문제 | 감도 좋은 USB 마이크로 교체하고 입력 게인(alsamixer) 조정 |
| 보호자 알림 | 휴대폰 브라우저의 보호자 화면이 서버에 직접 연결(WebSocket)해 경보 수신. 텔레그램은 사용하지 않음 |
| 모바일 | 네이티브 앱 대신 서버가 제공하는 모바일 웹. 설치가 필요 없고, 키오스크 화면과 같은 기술(HTML·JavaScript)로 만들 수 있음 |
| 서버 접속 방식 | HTTPS. 휴대폰 브라우저는 HTTPS 페이지에서만 카메라를 열 수 있으므로 서버에 인증서를 설정함 |
| 시연 네트워크 | 팀이 가져가는 공유기 또는 휴대폰 핫스팟 |
| 기존 코드 | 새 구조로 처음부터 다시 작성. 기존 시험 구현은 참고용으로 보관 |

## 확인이 필요한 결정

- 서버 PC의 GPU 유무와 실제 FPS (10/26 측정). GPU가 없으면 YOLO 모델 크기와 전송 FPS를 낮춤
- 서버 프레임워크 (제안: FastAPI. WebSocket 기본 지원, API 문서 자동 생성으로 웹 담당과 형식 맞추기 쉬움, 웹페이지도 함께 제공)
- 휴대폰 카메라로 감지했을 때의 상태 확인 방법: 근처에 Pi 스피커·마이크가 없으므로 음성 확인 없이 일정 시간 뒤 경보로 할지, 휴대폰이 안내 음성을 낼지
- 음성 확인 문구, 응답 대기 시간, 판정 임계값 (테스트 결과로 결정)
- 테스트 영상 촬영 동의와 보관 기간

## 알려진 한계 (발표 시 설명)

- 휴대폰에서 보호자 화면이 열려 있고(화면 켜짐) 서버와 같은 네트워크에 있을 때만 경보를 받습니다. 브라우저를 닫거나 다른 앱으로 넘어가면 경보를 놓칠 수 있습니다. 실제 서비스라면 푸시 알림과 외부망 서버가 필요합니다.
- 휴대폰 브라우저는 사용자가 화면을 한 번 누르기 전에는 소리를 내지 못하므로, 보호자 화면을 열 때 '알림 켜기' 버튼을 누르게 합니다.
- 서버가 꺼지거나 네트워크가 끊기면 감지가 멈춥니다. 현장 화면과 보호자 화면에 '감지 중단'을 표시하는 것까지가 이번 범위입니다.
- 영상이 기기 밖(같은 네트워크 안의 서버)으로 전송됩니다. 저장하지 않고 메모리에서만 처리하는 것으로 한정합니다.
