# 요구사항 초안

> 2026-10-25 재계획과 웹 기능 확정 반영. 구현 목표를 정리한 초안이며 완료 기능이나 확정된 성능을 뜻하지 않습니다.

## 기능 요구사항

| ID | 요구사항 | 시연 시 확인할 내용 |
| --- | --- | --- |
| F-01 | Pi와 휴대폰이 카메라 영상을 중앙 서버로 보내고, 서버가 장치별 연결 상태를 표시한다. | 장치 연결·끊김이 보호자 화면과 현장 화면에 보임 |
| F-02 | 서버가 영상에서 자세와 움직임을 분석해 장치별로 낙상 의심 상황을 판정한다. | 정상 동작과 낙상 의심 시나리오의 구분 결과 |
| F-03 | 낙상 의심 시 감지한 기기(Pi 또는 휴대폰 브라우저)가 안내 음성을 재생하고 응답을 녹음하며, 서버가 음성을 인식해 상태를 확인한다. | 안내 출력, 응답 인식과 분류 |
| F-04 | 확인 결과에 따라 해제 또는 경보를 결정한다. | 괜찮음, 도움 요청, 무응답, 장치 오류별 처리 |
| F-05 | 주요 이벤트를 장치, 시간, 상태와 함께 기록한다. | 발생·처리 이력 조회 |
| F-06 | 경보를 그 사용자의 보호자에게 웹 푸시와 보호자 화면으로 전달한다. | 브라우저를 닫아 둔 보호자 휴대폰에 알림 도착, 열려 있는 보호자 화면에 경보(소리·진동) |
| F-07 | Pi 현장 화면에서 현재 상태를 보고 '괜찮아요' 버튼으로 해제할 수 있다. | 상태 변화 표시, 버튼 해제 |
| F-08 | 보호자 화면에서 내가 보호하는 사용자의 현재 상태와 이벤트 기록을 볼 수 있다. | 기기별 상태, 최근 이벤트 목록 |
| F-09 | 휴대폰 브라우저의 카메라 감지 화면으로 휴대폰을 감지 장치로 쓸 수 있다. | 휴대폰 카메라 앞 낙상 연출 시 낙상 의심 판정 |
| F-10 | 이메일과 비밀번호로 회원가입, 로그인, 로그아웃할 수 있다. | 가입·로그인·로그아웃, 틀린 비밀번호 거부 |
| F-11 | 마이페이지에서 다른 회원을 보호자로 등록하고, 보호자는 요청을 수락할 수 있다. | 등록 요청 → 수락 → 보호자 화면에 사용자 표시 |
| F-12 | 사용자는 자기 계정에 기기(휴대폰, Pi)를 등록하고 목록을 볼 수 있다. | 휴대폰 자동 등록, Pi 기기 키 발급 후 접속 |
| F-13 | 사용자와 보호자는 볼 권한이 있는 기기와 이벤트만 볼 수 있다. | 연결되지 않은 계정으로는 상태·기록이 보이지 않음 |

## 통합 조건

- 서버 PC, Pi, 휴대폰이 시연장의 같은 네트워크(공유기 또는 핫스팟)에서 함께 동작해야 합니다.
- 서버나 네트워크가 끊기면 현장 화면과 보호자 화면에 감지 중단을 표시하고, 다시 연결되면 자동으로 복구합니다.
- 보호자 화면이 다시 연결되면 진행 중인 경보를 다시 받아야 합니다.
- 휴대폰 브라우저에서 카메라·마이크·웹 푸시를 쓰려면 서버를 HTTPS로 접속해야 합니다.
- 웹 푸시를 보내려면 서버 PC가 인터넷에 연결되어 있어야 합니다.

## 안전과 개인정보

- 안전한 연출 영상이나 공개 자료로 기능을 검증하고, 테스트를 위해 실제 위험한 낙상을 시도하지 않습니다.
- 카메라 영상은 같은 네트워크 안의 서버로만 보내고 저장하지 않습니다. 응답 녹음은 인식 후 지웁니다.
- 비밀번호는 해시로만 저장하고, 계정 정보는 이메일·이름·비밀번호 해시만 둡니다.
- 사람을 촬영하거나 음성을 수집할 때는 대상자의 동의를 받고, 접근 권한과 보관 기간을 정한 뒤 사용합니다.
- 프로토타입의 경보는 안전을 돕는 보조 수단이며 의료 판단이나 실제 구조 요청을 보장하지 않습니다.

정확도, 오경보율, 탐지 지연, 음성 응답 대기 시간 등 수치 목표는 아직 확정되지 않았습니다. 서버 PC FPS를 측정하고(10/26) 테스트 영상으로 시험한 뒤 측정 방법과 함께 기록합니다.
