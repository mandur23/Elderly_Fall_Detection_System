# 테스트 계획 초안

> 목적은 프로토타입의 기능과 한계를 확인하는 것입니다. 성능 수치는 테스트 후 기록합니다.

## 테스트 자료

- 공개 낙상 관련 자료의 사용 조건을 확인한 뒤 활용합니다.
- 팀 내 테스트 영상은 동의를 받고 안전하게 연출합니다 (매트 위, 천천히).
- 다양한 조명, 거리, 가림, 일반적인 앉기·눕기 동작을 포함해 오경보를 확인합니다.
- 같은 영상을 서버에 반복 입력할 수 있게 해 임계값을 바꿀 때마다 같은 조건으로 비교합니다.

## 기능별 확인 항목

| ID | 상황 | 확인할 결과 |
| --- | --- | --- |
| T-01 | Pi 카메라 연결 및 정상 움직임 | 서버에 프레임 수신, 정상 상태 표시 |
| T-02 | 안전하게 연출한 낙상 (Pi 카메라) | 낙상 의심 전환 및 Pi 안내 음성 |
| T-03 | 음성 확인에 응답 ('괜찮아요', '도와주세요', '안 괜찮아요') | 응답 규칙에 따른 해제·경보와 기록 |
| T-04 | 음성 확인에 응답하지 않음 | 대기 시간 후 경보, 보호자 화면 경보 수신, 기록 |
| T-05 | 앉기·눕기 등 일상 동작 | 불필요한 경보 여부 |
| T-06 | 카메라·마이크·스피커 연결 오류 | 오류 상태 표시와 복구 |
| T-07 | 서버 연결 끊김 (서버 종료, 공유기 분리) | Pi 화면·보호자 화면에 감지 중단 표시, 재연결 후 자동 복구 |
| T-08 | 서버 재시작 | 이벤트 기록 유지, 진행 중이던 이벤트 처리 |
| T-09 | 보호자 화면 재연결 | 새로고침하거나 다시 열어도 진행 중인 경보가 다시 보임 |
| T-10 | 휴대폰 카메라 감지 화면에서 낙상 연출 | 낙상 의심 판정, 보호자 화면 경보 |
| T-11 | Pi와 휴대폰을 동시에 연결 | 장치별로 따로 판정·기록되고 서로 간섭하지 않음 |
| T-12 | 1~2m 거리에서 음성 응답 (새 마이크) | 인식 성공률 기록 |
| T-13 | 카메라 감지 화면을 열어 둔 채 휴대폰을 일정 시간 방치 | 화면이 꺼지지 않고 감지가 계속됨 |
| T-14 | 보호자 휴대폰의 브라우저를 닫은 상태에서 경보 | 웹 푸시 알림 도착, 누르면 보호자 화면이 열림 |
| T-15 | 회원가입, 로그인, 틀린 비밀번호, 로그아웃 | 정상 처리와 거부, 로그아웃 후 보호 화면 접근 불가 |
| T-16 | 보호자 등록 요청·수락·해제 | 수락 후에만 경보·기록을 받고, 해제하면 더 받지 않음 |
| T-17 | 연결되지 않은 다른 계정으로 접속 | 남의 기기·이벤트가 보이지 않고 해제도 안 됨 |
| T-18 | 휴대폰 카메라 감지 중 낙상 → 휴대폰 음성 확인 (응답·무응답·마이크 권한 거부) | 응답 규칙에 따른 해제·경보 |
| T-19 | 관리자 페이지를 서버 PC와 같은 Wi-Fi의 휴대폰에서 각각 열기 | 서버 PC에서만 열리고 휴대폰에서는 404. 계정 정지 시 로그인·카메라 연결이 막히고 해제하면 복구 |

## 측정 및 기록

- 각 시나리오의 입력 자료, 장치, 서버 PC 사양, 모델 버전과 판단 기준을 기록합니다.
- 낙상 감지 성공·실패, 오경보, 낙상부터 보호자 웹 푸시 도착까지 걸린 시간, 서버 처리 FPS, 음성 인식 결과를 구분합니다.
- 시험이 끝날 때마다 서버 PC에서 관리자 페이지(`/admin`)의 **이벤트·통계** 탭을 열어 이벤트마다 검토 라벨을 답니다.
  - 실제 낙상, 연출 낙상(시험으로 넘어진 경우), 일상 동작(앉기·눕기 등을 낙상으로 본 경우), 오경보(그 밖에 잘못 울린 경우) 중 하나를 고르고, 영상 번호·조명·거리 같은 조건을 메모(200자)에 적습니다.
  - 오경보율은 라벨을 단 이벤트 중 '오경보'의 비율로 통계에 바로 나옵니다. 라벨이 없는 이벤트는 계산에서 빠지므로 빠짐없이 답니다.
  - 같은 화면에서 평균 시간(의심→해제, 의심→경보, 경보→해제)과 웹 푸시 성공률도 봅니다. 보호자 화면이 닫혀 있어 화면 알림을 못 보낸 것은 장애가 아니므로 화면 알림 전달률은 참고만 합니다.
- `CSV 다운로드`로 지금 필터(기간·판정·라벨·사용자)의 이벤트를 내려받아 시험 기록에 붙입니다. 엑셀에서 바로 열리며(UTF-8 BOM), 판정 특징값(하강 속도 등)이 들어 있어 임계값을 바꿀 때 비교 자료로 씁니다.
- 수치 목표와 합격 기준은 서버 PC FPS 측정 후 팀이 합의하여 이 문서에 추가합니다.
- 실패 사례는 재현 조건과 원인을 남기고 수정 후 같은 시나리오로 다시 확인합니다.

이 테스트는 교육용 시연의 동작 확인이며, 의료기기 수준의 성능 검증을 의미하지 않습니다.
